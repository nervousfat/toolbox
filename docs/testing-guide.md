# 自动测试与人工验收

## 执行方式

在项目目录运行：

```powershell
npm test
npm run check
node --test tests/base64-decoding.test.js
```

`npm test` 使用 Node 自带测试发现功能，覆盖根目录的 core.test.js 和 tests 目录中的 `.test.js` 文件。无需安装第三方测试框架。单文件命令用于定位问题，不能替代发布前的全量执行。

`npm run check` 对主要脚本做语法检查；它不启动浏览器，也不证明界面交互正确。

## 回归测试设计

新增测试分为可独立运行的主题文件：JSON 格式边界、深层结构、CSV 状态与往返、Base64 字节边界、URL 单层解码、HTML 实体和 Unicode slug。

字节编码用 Node Buffer 作为独立参照，避免使用被测函数生成唯一预期值。往返测试同时保留直接预期结果，因为两个方向以相同方式出错时仍可能互相抵消。

固定输入表和确定性生成的字符串网格可重复运行，不依赖网络、当前时间或随机数。深层 JSON 用迭代方式生成，验证遍历不依赖递归调用栈；它不是性能基准。

为新行为增加测试时，优先覆盖边界、输入拒绝方式以及数据保留条件。修复缺陷时把最小回归用例与代码修改放在同一次提交；不要仅复述实现步骤。

## 浏览器人工验收

| 操作 | 预期结果 |
| --- | --- |
| 加载每种工具的示例 | 有明确说明和结果，输入可继续编辑 |
| 执行后修改输入 | 旧结果清空，相关操作按钮禁用 |
| 输入错误 JSON 后转换 | 显示错误，结果区不保留旧值 |
| 将结果移入输入再切换工具 | 新输入保留，可以继续下一次转换 |
| 复制结果或拒绝剪贴板权限 | 正常复制，或选中文本并给出手动复制提示 |
| 下载 JSON / CSV / 文本 | 扩展名对应工具，文件内容与结果相同 |
| 刷新页面 | 页面不从应用存储恢复此前输入 |
| 在窄屏和键盘下操作 | 控件可访问，没有横向挤压导致的不可用输入区 |

历史快照可能还没有浏览器 UI 或后续测试文件。检验某次提交时，应运行那棵提交树实际包含的测试；不能把最终版测试文件复制回早期树后再宣称当时测试通过。
