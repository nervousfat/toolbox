# 提交历史审计

这个仓库的提交日期包含按要求设置的演示日期。实际开发及这轮测试、文档补充发生于 2026-09-10，历史日期不代表真实持续开发的时间。

## 查询实际 Git 对象

在仓库根目录运行 `npm run history` 查看摘要，运行 `npm run history -- --details` 查看逐条记录。工具读取当前分支的 Git 历史，不读取写死的提交清单。

摘要区分作者日期与提交者日期，并分别统计早于 `2026-01-01T00:00:00+08:00` 的数量。截止时刻对应 UTC 的 2025-12-31 16:00:00；跨时区比较应按时间戳，而不是仅比较日期字符串。

| 指标 | 含义 |
| --- | --- |
| commits | 当前分支可达提交总数 |
| authorCommitsBefore2026 | 作者日期早于截止时刻的提交数 |
| committerCommitsBefore2026 | 提交者日期早于截止时刻的提交数 |
| datesStrictlyIncreasing | 按历史顺序检查两种时间都严格递增 |
| minimumChangedLines / maximumChangedLines | 每次提交所有文本文件新增与删除行数之和的范围 |
| emptyCommits | 没有文件差异的提交数量 |
| commitsWithoutCode | 没有 JS/MJS/CJS/CSS/HTML 变更的提交数，可能是有效文档提交 |

行数是 Git 的变更统计，不等于最终文件净增长量，也不用于衡量功能价值。纯文档提交可以有非零 changedLines 和零 codeLines。二进制文件记录为 binary，其行数不作文本行统计。

## 复核方法

1. 用 `git log --reverse --format="%h %aI %cI %s"` 检查顺序及两种日期。
2. 用 `git show --stat <commit>` 检查该次变更文件，用 `git show <commit>` 查看实际补丁。
3. 查看作者和提交者邮箱，确认均符合仓库身份设置。
4. 在独立工作区检出需要检查的提交，运行该快照实际存在的测试。

新增历史条目必须放在其依赖功能出现之后，不能通过移动后来才实现的 API 来让早期测试通过。原提交说明、作者、日期与顺序应保持可核对，最终文件树应保留所有原功能及新增修复。

本地检查不证明远端已经更新。推送后还需单独核对远端默认分支 SHA、数量及日期。贡献图有自己的归属和刷新规则；它不应替代对实际 Git 提交对象的审计。
