# 输入规模与错误排查

## 规模限制

浏览器执行转换前用 UTF-8 字节数检查输入，大于 1,000,000 字节时拒绝运行，恰好等于该值可以继续。这里的 1 MB 是十进制字节数，不是字符数，也不是 1 MiB。

core.js 的纯函数没有统一的输入长度上限。直接在 Node 中调用时，调用方需要控制输入规模。转换同步执行，可能临时同时持有输入、解析结果和输出；格式化、HTML 转义或 Base64 编码的输出也可能大于输入。输入上限不保证任意结构都能在固定时间完成。

## 按症状检查

| 现象 | 检查方法 |
| --- | --- |
| JSON 转换失败 | 检查引号、逗号、注释和根值，先用最小 JSON 片段复现 |
| JSON 数字发生变化 | 检查是否超出安全整数范围；回到原始数据源，把标识符作为字符串导出 |
| CSV 列数不一致 | 检查记录中的逗号是否正确引用，以及是否多出空白行 |
| CSV 引号位置错误 | 关闭引号后只允许逗号、换行或结束，不接受尾部空格 |
| Base64 失败 | 检查标准字母表、完整 padding，以及原始内容是否确实为 UTF-8 文本 |
| URL 解码失败 | 检查残缺百分号和非法 UTF-8；确认没有把普通百分号误当编码 |
| 复制失败 | 使用应用已经选中的结果手动复制，检查浏览器权限 |
| 刷新后内容消失 | 应用没有保存输入的持久化逻辑；从自己保存的原文件恢复 |
| 结果突然清空 | 输入变化、工具切换和转换错误都会清空结果，重新执行所需转换 |

## 启动问题

需要 Node.js 22 或更新版本。在 toolbox 目录运行 `npm start`，通过终端显示的本机 HTTP 地址访问，避免直接打开 HTML 文件导致模块加载限制。

默认端口是 4173。若端口占用，可在 PowerShell 当前窗口执行：

```powershell
$env:PORT=4174
npm start
```

服务只监听 127.0.0.1；其他设备不能通过这份启动配置访问。不要为解决模块加载问题关闭浏览器安全设置。

## 提交可复现问题

记录 Node 或浏览器版本、所选工具、最小输入、期望结果和实际提示。用不含个人信息的等价文本复现；编码后的内容仍可能包含原数据。附上 `npm test` 或 `npm run check` 的失败输出有助于定位逻辑问题。
