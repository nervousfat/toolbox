# Unicode、Base64、URL 与 HTML 文本

## Base64

编码先用 UTF-8 把文本转换成字节，再输出标准 Base64 字母表。解码接受空白分隔，但需要完整的 padding，且尾部未使用的位必须为零。不接受 URL-safe Base64 的 `-` 和 `_`。

解码结果必须是有效 UTF-8。任意二进制文件即使 Base64 格式正确，也可能无法作为文本解码。文本开头的 U+FEFF 会保留，不会在解码时静默丢失。

编码使用 TextEncoder；JavaScript 字符串里的孤立 UTF-16 surrogate 会转换为替代字符。因此只有有效 Unicode 文本可期待逐字符往返。Base64 是表示方式，不提供加密或访问控制。

## URL 组件

输入应该是一个路径片段或参数值，不是完整网址。编码保留字母、数字、`-._~`，并把其他字符编码为 UTF-8 百分号序列。

例如参数值 `a+b c` 编码为 `a%2Bb%20c`。解码时裸 `+` 保持 `+`，不按表单编码规则变成空格。

解码一次只去掉一层编码：`%252F` 得到 `%2F`。除非数据格式明确规定嵌套编码，否则不要重复解码。孤立 surrogate、残缺百分号序列或无效 UTF-8 会导致错误，不返回部分结果。

## HTML 实体作为文本

转义替换 `& < > " '` 五类字符。已经存在的实体也作为普通输入转义，因此 `&amp;` 会变成 `&amp;amp;`。它适用于表示文本，不是通用 HTML 清洗器或所有属性上下文的编码器。

解码支持 amp、lt、gt、quot、apos、nbsp 六个名称，名称大小写不敏感；同时支持带分号的十进制和十六进制数字实体。未知名称及不完整形式保持原样。

零、surrogate 区间和超出 Unicode 上界的数字实体变为 U+FFFD。一次替换不会递归展开新产生的实体。页面把结果放入文本框，不将解码后的内容作为 HTML 插入。

## slug

slug 使用 NFKD 规范化，去掉组合标记，转为小写，把连续的非字母/数字替换成连字符，然后清理首尾连字符。中文等非拉丁字母会保留；这不是拼音或拉丁转写。

不同名称可能得到同一个 slug，纯符号输入可能得到空字符串。用于文件名、路由或记录标识前，应自行处理空值与碰撞，不能依赖它生成唯一 ID。
